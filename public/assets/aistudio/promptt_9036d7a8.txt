PROJECT CONTEXT

Audit dan modifikasi repository NodePanel terbaru yang sudah tersedia.

Frontend sudah memiliki custom UI components, service API, WebSocket manager, server detail workspace, package manager, dan testing infrastructure. Jangan menganggap semuanya sempurna hanya karena komponennya sudah tersedia.

Fokus pada implementasi aktual dan kekurangan fungsional yang ditemukan.

Jangan melakukan rewrite backend tanpa alasan. Jangan mengganti komponen yang sudah benar hanya untuk menggantinya. Namun, jika sebuah modul lama menghambat fitur yang diminta, refactor modul tersebut dengan desain yang benar dan regression tests.

PRIORITY 1 — REAL-TIME TERMINAL YANG BENAR-BENAR MENGIKUTI PROSES TERMUX

Masalah aktual

Pada "src/components/ServerDetailView.tsx", handler "handleRunNpmInstall" memanggil "installServerDeps(serverId)" lalu baru menambahkan output setelah Promise selesai.

Pada backend, route yang menjalankan "npm install" juga perlu diperiksa karena implementasi "runCommandAsync()" mengumpulkan stdout dan stderr ke buffer sebelum mengembalikan hasil.

Akibatnya, pengguna belum tentu melihat output proses secara langsung. Jangan menyebut sistem ini real-time hanya karena hasil akhirnya ditampilkan di terminal.

Target

Bangun terminal monitoring yang menampilkan output proses secara live, dengan pengalaman seperti terminal Termux sungguhan.

Ketika user menjalankan:

- "npm install"
- "npm run build"
- "npm start"
- "npm test"
- Git clone
- Package installation
- Command lain yang memang didukung terminal project

User harus dapat memantau output ketika proses masih berjalan, bukan hanya setelah proses selesai.

A. Gunakan proses nyata pada environment yang benar

Pertama, audit bagaimana NodePanel dijalankan:

- Native Termux Android.
- Ubuntu melalui PRoot.
- Linux host.
- Environment lain yang benar-benar didukung.

Gunakan runtime detection dan working directory yang sesuai dengan server yang sedang dikelola.

Jika panel dijalankan di Termux native, command harus berjalan pada environment Termux yang benar. Jika server menggunakan Ubuntu PRoot, command harus dijalankan di environment PRoot yang sesuai.

Jangan mengasumsikan semua deployment adalah native Termux.

Jangan membuat terminal simulasi, output palsu, progress palsu, atau sekadar menambahkan animasi loading.

B. Implementasikan streaming stdout dan stderr

Gunakan "child_process.spawn()" dengan argument array dan "shell: false" untuk command yang dapat dieksekusi secara aman melalui executable dan argumen terstruktur.

Buat process/job manager yang mampu:

1. Membuat job dengan ID unik.
2. Menyimpan command, server ID, working directory, status, start time, dan exit code.
3. Mengirim stdout dan stderr ketika data diterima.
4. Menyimpan urutan output secara konsisten.
5. Mengirim status started, running, completed, failed, cancelled, atau timed out.
6. Menangani process spawn errors dan exit signals.
7. Membersihkan resource setelah proses selesai.
8. Menjaga batas penggunaan memori untuk output yang besar.

Gunakan mekanisme streaming yang cocok dengan arsitektur aktual, seperti WebSocket yang sudah tersedia atau endpoint streaming tambahan jika benar-benar diperlukan.

Jangan membuat WebSocket kedua yang fungsinya tumpang tindih tanpa alasan.

Setiap event harus memiliki identitas job, server, dan sequence atau metadata yang cukup agar frontend dapat mengurutkan output dan menghindari duplikasi.

C. ANSI colors dan terminal rendering

Pertahankan warna terminal yang memang dihasilkan proses.

Contoh:

- Hijau untuk keberhasilan.
- Merah untuk error.
- Kuning untuk warning.
- Cyan atau warna lain sesuai output tool.
- Dim text untuk informasi sekunder.

Gunakan terminal renderer yang benar jika diperlukan, misalnya xterm.js beserta dukungan ANSI dan fit addon, setelah mengevaluasi kompatibilitas dan ukuran dependency.

Jangan mengandalkan "<pre>" biasa untuk menampilkan ANSI escape codes secara mentah.

Tangani:

- ANSI color sequences.
- Progress updates yang memakai carriage return.
- Output multiline.
- Unicode dan karakter Android.
- Terminal resize.
- Auto-scroll ketika pengguna berada di bagian paling bawah.
- Jangan memaksa auto-scroll jika user sedang membaca output sebelumnya.
- Clear display tanpa menghapus history job yang tersimpan.
- Copy output.
- Download log jika sesuai.
- Search dalam output untuk proses panjang.

Bedakan stream stdout, stderr, dan system events.

D. Jangan memalsukan interactive shell

Bedakan antara:

1. Command execution terminal yang berjalan satu proses per command.
2. Persistent interactive shell/PTY yang mempertahankan session, working directory, environment, dan interactive program.

Jika ingin pengalaman terminal Termux sesungguhnya, evaluasi apakah PTY dan pseudo-terminal integration diperlukan.

Jangan menyebut terminal sebagai full interactive shell jika implementasinya belum mendukung PTY, input interaktif, resize, dan session persistence.

Jangan membuat shell baru untuk setiap event output.

E. Command lifecycle

Tambahkan:

- Start command.
- Cancel/terminate command.
- Exit code dan signal.
- Runtime duration.
- Timeout.
- Output streaming.
- Running-job indicator.
- Reconnect dan output replay.
- Riwayat proses yang selesai.
- Error handling ketika proses gagal.

Untuk proses yang sulit dihentikan, evaluasi process group atau mekanisme termination yang sesuai dengan OS target. Jangan sampai hanya parent process yang berhenti sementara child process tetap hidup.

Jangan menghentikan seluruh panel ketika user membatalkan command.

Jangan menjalankan ulang command secara otomatis ketika WebSocket reconnect.

Command execution yang mengubah server wajib mempunyai authorization dan validasi sesuai security model project.

F. Integration npm install dengan terminal

Ubah alur instalasi dependency agar proses yang sesungguhnya dipantau melalui job manager yang sama.

Ketika user menekan Install Dependencies:

1. Backend membuat job.
2. Frontend segera menerima job ID.
3. UI menampilkan job sebagai running.
4. Output aktual diterima secara streaming.
5. Progress dan status diperbarui selama proses berjalan.
6. User dapat pindah halaman tanpa kehilangan job.
7. Ketika kembali, frontend mengambil status dan output terbaru.
8. Saat proses selesai, UI menampilkan exit code dan durasi.
9. Jika gagal, tampilkan error aktual dan log yang relevan.
10. Setelah selesai, refresh package/dependency state bila diperlukan.

Jangan menunggu seluruh "npm install" selesai sebelum menampilkan output.

Jangan menjalankan dua instalasi dependency bersamaan pada server dan working directory yang sama jika dapat menyebabkan lock contention atau kerusakan "node_modules".

Jangan menyatakan "npm install" berhasil hanya karena proses spawn berhasil. Gunakan exit code proses yang sebenarnya.

PRIORITY 2 — PERSISTENT BACKGROUND JOBS SAAT PINDAH TAB

Masalah aktual

Ketika user berpindah tab saat proses berjalan, status instalasi dan output terasa hilang. User tidak tahu apakah proses masih berjalan, sudah selesai, atau gagal.

Arsitektur yang diwajibkan

Pisahkan lifecycle process dari lifecycle komponen React.

Backend menjadi sumber kebenaran status job.

Frontend memiliki job state yang dapat diakses lintas halaman, bukan hanya local state di "ServerDetailView.tsx".

Implementasikan sesuai kebutuhan:

- Global job store atau equivalent state manager.
- Job registry pada backend.
- Job status API.
- Job history API.
- Output replay atau cursor-based retrieval.
- WebSocket subscriptions untuk live updates.
- Reconnect reconciliation.
- Running jobs panel.
- Persistent job notification.
- Toast atau completion notification.

Ketika komponen terminal di-unmount:

- Job tidak ikut dibatalkan.
- Backend process tidak ikut dihentikan.
- Subscription komponen dibersihkan.
- Global job state tetap tersedia.

Ketika user kembali:

- Ambil snapshot status terbaru.
- Subscribe ke event selanjutnya.
- Ambil output yang terlewat menggunakan cursor/sequence.
- Deduplicate events.
- Jangan menjalankan ulang command.

Tangani reconnect ketika:

- User pindah tab browser.
- Browser masuk background.
- Koneksi internet terputus.
- WebSocket disconnect.
- Dashboard melakukan navigasi.
- Browser di-refresh.

Jika user melakukan refresh, job tetap bisa ditemukan selama backend panel tetap berjalan dan job masih valid.

Dokumentasikan batas persistence. Jangan mengklaim proses bertahan setelah backend panel mati kecuali memang ada supervisor atau mekanisme recovery yang mendukungnya.

Simpan log secara bounded dan aman. Terapkan batas jumlah job aktif, ukuran output, retention, serta cleanup untuk job lama.

PRIORITY 3 — FLOATING NAVIGATION DAN MOBILE-FIRST EXPERIENCE

Gunakan gambar referensi pengguna sebagai inspirasi bentuk floating navigation, bukan sebagai desain yang disalin secara langsung.

NodePanel harus tetap terlihat seperti developer control panel profesional.

Desktop

Bangun application shell dengan:

- Sidebar yang dapat collapse.
- Top navigation yang menampilkan page title, connection state, dan action penting.
- Main content area yang fleksibel.
- Running jobs indicator yang dapat diakses dari halaman mana pun.
- Global notifications.
- Context-aware actions.

Mobile

Buat bottom navigation berbentuk floating pill:

- Posisi fixed di atas safe area.
- Background charcoal yang sedikit translucent.
- Border tipis dan shadow yang halus.
- Active tab menggunakan pill/highlight yang jelas.
- Icon dan label memiliki ukuran yang konsisten.
- Target sentuh minimal sekitar 44 × 44 CSS pixels.
- Tidak menutupi form, terminal input, modal, atau elemen penting.
- Menghormati safe-area inset pada perangkat Android.
- Menyediakan padding bawah yang sesuai pada halaman.
- Tidak menggunakan animasi berlebihan.

Evaluasi tab yang memang paling berguna dari fitur aktual, misalnya:

- Overview.
- Servers.

- Settings.

Jangan memaksakan semua fitur menjadi tab utama. Gunakan menu tambahan untuk fitur sekunder jika diperlukan.

- Berikan mode fullscreen bila bermanfaat.

PRIORITY 4 — CREATE SERVER INPUT BUG DAN RESPONSIVENESS

Gejala

Saat user mengisi nama server, repository URL, branch, atau field lain pada form Create Server, input terasa tidak normal atau mengalami perubahan yang sangat cepat.

Jangan langsung menyimpulkan penyebabnya. Reproduksi bug terlebih dahulu.

Audit:

- "src/components/CreateServerModal.tsx"
- Input components di "src/components/ui/".
- Validation utilities.
- State update flow.
- Effects dan dependencies.
- Git repository validation.
- Debounce dan async request behavior.
- React rerender dan remount.
- Browser input events.
- API requests saat mengetik.
- Modal lifecycle.
- Network timing.

Perilaku yang diharapkan

1. Input menerima karakter secara normal tanpa kehilangan, duplikasi, atau perubahan urutan karakter.
2. Fokus tidak hilang ketika mengetik.
3. Field tidak di-reset oleh rerender.
4. Tidak ada API request mahal untuk setiap karakter jika tidak diperlukan.
5. Validasi lokal ringan dapat dilakukan saat input berubah.
6. Validasi remote dilakukan pada waktu yang sesuai, misalnya saat blur atau submit, atau menggunakan debounce bila memang dibutuhkan.
7. Async validation tidak boleh menimpa hasil yang lebih baru dengan hasil request lama.
8. Error ditampilkan dekat field terkait.
9. Loading state hanya muncul ketika operasi asynchronous benar-benar berjalan.
10. Form tidak terkirim berulang.
11. User dapat mengoreksi repository URL dan branch tanpa gangguan.
12. Modal tetap usable di layar kecil dan ketika keyboard muncul.

Gunakan stable component identity, controlled inputs yang benar, dan stable keys.

Jangan menggunakan debounce pada setiap "onChange" sebagai solusi universal. Pastikan input lokal tetap responsif dan hanya request asynchronous yang perlu dibatasi.

Create Server operation

Audit juga alur:

- Template creation.
- Git repository clone.
- Branch selection.
- Name derivation.
- Package installation otomatis.
- Server record creation.
- Error handling.
- Partial failure dan cleanup.

Operasi berat seperti Git clone dan npm install harus dikelola sebagai jobs yang bisa dipantau. Jangan membuat user menunggu request panjang tanpa status.

Pastikan server record dan file workspace tidak tertinggal dalam kondisi setengah dibuat jika provisioning gagal.

Jangan menghapus data valid atau mengulang provisioning secara membabi buta saat retry.

IMPLEMENTATION AND DELIVERY RULES

1. Baca dan pahami implementasi aktual sebelum mengubahnya.
2. Reproduksi gejala dan kumpulkan bukti.
3. Dokumentasikan root cause.
4. Implementasikan perubahan dengan scope sekecil mungkin tetapi menyelesaikan masalah secara benar.
5. Tambahkan regression tests.
6. Jalankan static, unit, integration, E2E, dan load tests sesuai environment.
7. Perbaiki semua regression akibat perubahan.
8. Update "AUDIT.md", "TESTING.md", dan buat "TERMINAL_JOBS.md" jika sesuai.
9. Jangan meninggalkan placeholder atau fake implementation.
10. Jangan menyatakan fitur selesai jika baru berupa UI tanpa backend integration.

Pada laporan akhir, jelaskan:

- Mengapa output terminal sebelumnya tidak realtime.
- Bagaimana streaming stdout/stderr sekarang bekerja.
- Bagaimana job tetap berjalan saat user pindah tab.
- Apa yang terjadi saat WebSocket reconnect atau browser refresh.
- Apakah implementasi mendukung persistent shell/PTY atau hanya command jobs.
- Root cause Create Server input issue.
- Bagaimana floating navigation menangani safe area dan keyboard.
- Test mana yang benar-benar PASS, FAIL, atau NOT RUN.

Tujuan akhirnya adalah terminal yang benar-benar berguna untuk developer, progress yang tidak hilang ketika navigasi berubah, dan UI mobile yang profesional tanpa mengorbankan stabilitas server.
